## 1. La historia real: ¿Qué pasó en la máquina?

En una sesión de desarrollo típica, realizamos varias acciones:
1. Instalamos **MySQL** nativo para unas prácticas.
2. Instalamos **PostgreSQL** para comparar motores.
3. Abrimos navegadores (**Chrome**, **Comet**) con muchas pestañas de documentación, vídeos y tutoriales.
4. Más tarde abrimos **Docker Desktop** para probar contenedores.

Horas después, notas el chasis caliente y la batería cayendo a toda velocidad. Le das a **Apagar**, pero la pantalla sigue encendida.

### ¿Por qué ocurrió esto?
1. **Los motores SQL se instalan como "Servicios Residentes":** Cuando instalas MySQL o PostgreSQL con los instaladores tradicionales, se configuran para **iniciarse automáticamente cada vez que enciendes el ordenador** y quedarse esperando peticiones en memoria RAM de forma indefinida, aunque tú no tengas ninguna terminal abierta.
2. **Procesos huérfanos / navegadores en segundo plano:** Aplicaciones como Chrome o Comet pueden mantener abiertos procesos de renderizado auxiliares o instancias en segundo plano.
3. **Por qué macOS / Windows no se apagan de golpe:** El sistema operativo es prudente. Si hay aplicaciones con pestañas activas, procesos con directivas contra el reposo (*assertions*), descargas o diálogos pendientes, el sistema **cancela el apagado silenciosamente** para evitar que pierdas información no guardada.

## 2. Conceptos básicos de Sistemas Operativos

### ¿Qué es un Proceso y qué es el PID?
* **Programa:** Es el código guardado en el disco duro (un archivo `.exe` o binario inerte). Piensa en él como una **receta de cocina en un libro**.
* **Proceso:** Es ese programa **cobrando vida en la memoria RAM y consumiendo CPU**. Es el cocinero siguiendo la receta en los fogones.
* **PID (Process ID):** Cada vez que un proceso nace, el sistema operativo le asigna un número identificador único e irrepetible (como su número de DNI o pasaporte). Si hay 3 ventanas de Chrome, cada una tendrá un **PID** diferente.

### Primer plano vs. Segundo plano
* **Primer plano (Foreground):** Ves la ventana, interactúas con ella, y si cierras la ventana con la cruz o pulsas `Ctrl + C` en la consola, el proceso muere.
* **Segundo plano (Background / Daemons / Servicios):** No tienen ventana ni icono en el Dock o barra de tareas. Trabajan "en la sombra". En Linux y macOS se les llama tradicionalmente **Daemons** (demonios) y sus nombres suelen terminar en `d` (por ejemplo, `mysqld`, `systemd`, `sshd`). En Windows se les llama **Servicios**.

### ¿Por qué una base de datos se queda abierta para siempre?
Un servidor de base de datos como MySQL está diseñado para empresas y servidores web que deben atender clientes 24 horas al día, 7 días a la semana. Por eso, al instalarlo en tu portátil, asume la misma mentalidad: **se queda encendido siempre** esperando conexiones en el puerto `3306`.

## 3. Diagnóstico y control en Linux / macOS

### El comando `ps` (Process Status)
El comando `ps` es la herramienta reina en sistemas Unix para fotografiar el estado de los procesos.

```bash
# Ver los procesos con su consumo de CPU y memoria
ps aux
```

💬 **¿Qué significan las letras `aux`?**
* `a` (all): Muestra los procesos de todos los usuarios, no solo los tuyos.
* `u` (user): Muestra el usuario dueño del proceso, el porcentaje de `%CPU` y `%MEM`.
* `x`: Muestra también los procesos que **no tienen una terminal asociada** (es decir, los demonios y servicios que corren en segundo plano).

#### Para ver directamente qué está quemando tu procesador:
```bash
# Lista los 10 procesos que más CPU están gastando ahora mismo
ps -eo pid,pcpu,pmem,comm | sort -k 2 -nr | head -n 10
```

### Ver el consumo en tiempo real con `top` / `htop`
* Ejecuta `top` en tu terminal para ver una tabla dinámica interactiva que se actualiza cada segundo.
* En la cabecera verás el **Load Avg** (promedio de carga de trabajo) y el `% CPU Idle` (porcentaje de procesador libre y descansando).
* Para salir de `top`, pulsa la tecla `q`.

### Cerrar procesos con seguridad: `kill -15` vs `kill -9`

Cuando un proceso se queda colgado o consumiendo batería, podemos pedirle que termine usando el comando `kill` seguido de su **PID**:

```bash
kill 12345
```

> [!IMPORTANT]
> **La diferencia crucial entre señales:**
>
> 1. `kill -15 <PID>` (o simplemente `kill <PID>`): Envía la señal **SIGTERM** (Terminación amable). Le dice al programa: *"Por favor, guarda lo que tengas pendiente, cierra los archivos, limpia la memoria y sal ordenadamente"*. **Esta es siempre la primera opción recomendada.**
> 2. `kill -9 <PID>`: Envía la señal **SIGKILL** (Muerte forzosa e inmediata). Equivale a arrancarle el cable de corriente. El programa no tiene tiempo de guardar nada. Solo debe usarse si el proceso está completamente congelado y no responde a `kill -15`.

### ¿Por qué mi usuario normal no puede apagar MySQL o Postgres? (`sudo`)
En sistemas Linux y macOS existe una jerarquía estricta de seguridad:
* Un usuario normal solo puede cerrar **sus propios procesos**.
* MySQL y PostgreSQL suelen ejecutarse bajo usuarios especiales del sistema (como `_mysql` o `postgres`) tutelados por el superusuario `root`.
* Si intentas hacer `kill` al PID de MySQL sin permisos, recibirás: `Operation not permitted`.
* Para detenerlos limpiamente necesitas privilegios de administrador con `sudo`:

```bash
# Detener el servicio de MySQL en macOS
sudo /usr/local/mysql/support-files/mysql.server stop

# Detener MySQL en Linux (Ubuntu/Debian)
sudo systemctl stop mysql

# Detener PostgreSQL 15 en macOS
sudo /Library/PostgreSQL/15/bin/pg_ctl -D /Library/PostgreSQL/15/data stop

# Detener PostgreSQL en Linux
sudo systemctl stop postgresql
```

## 4. Equivalente en Windows (PowerShell y Administrador de Tareas)

Si tú o tus compañeros trabajáis en Windows, los conceptos son exactamente los mismos, pero las herramientas cambian de nombre.

### Método Gráfico: El Administrador de Tareas
* Pulsa `Ctrl + Shift + Esc`.
* En la pestaña **Procesos**, haz clic en la columna **CPU** o **Memoria** para ordenar de mayor a menor consumo.
* En la pestaña **Servicios**, busca `MySQL80` o `postgresql-x64-XX`.

### Método Terminal: PowerShell

En Windows PowerShell disponemos de cmdlets muy potentes:

#### 1. Ver qué procesos consumen más recursos:
```powershell
# Ver los 10 procesos con mayor uso de CPU
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 -Property Id, ProcessName, CPU, WorkingSet
```

#### 2. Cerrar un proceso por su ID o Nombre:
```powershell
# Cierre amable (equivalente a kill -15)
Stop-Process -Id 1234

# Cierre por nombre de programa
Stop-Process -Name "chrome"

# Cierre forzado si no responde (equivalente a kill -9)
Stop-Process -Id 1234 -Force
```

#### 3. Gestionar los Servicios de Bases de Datos en Windows:
Para gestionar servicios en Windows, abre PowerShell como **Administrador**:

```powershell
# Ver el estado del servicio de MySQL
Get-Service -Name "*mysql*"

# Detener el servicio de MySQL
Stop-Service -Name "MySQL80"

# Detener el servicio de PostgreSQL
Stop-Service -Name "postgresql*"
```

## 5. Tabla Comparativa de Comandos

| Acción | Linux / macOS (Bash / Zsh) 🐧 🍎 | Windows (PowerShell) 🪟 |
| :--- | :--- | :--- |
| **Listar todos los procesos** | `ps aux` | `Get-Process` (o alias `ps`) |
| **Filtrar un proceso específico** | `pgrep -fl mysql` o `ps aux \| grep mysql` | `Get-Process -Name "*mysql*"` |
| **Ordenar por CPU descendente** | `ps -eo pid,pcpu,comm \| sort -k 2 -nr` | `Get-Process \| Sort-Object CPU -Desc` |
| **Cierre amable (Recomendado)** | `kill <PID>` o `kill -15 <PID>` | `Stop-Process -Id <PID>` |
| **Cierre forzado (Emergencia)** | `kill -9 <PID>` | `Stop-Process -Id <PID> -Force` |
| **Ver estado del servicio DB** | `brew services list` o `systemctl status mysql` | `Get-Service -Name "MySQL*"` |
| **Detener servicio DB** | `sudo systemctl stop mysql` | `Stop-Service -Name "MySQL80"` |

## 6. Cómo pedir ayuda a Antigravity (IA) con seguridad

Cuando notas que tu ordenador va lento, está caliente o se bloquea, la inteligencia artificial de **Antigravity** puede auditar el sistema por ti en cuestión de segundos.

Sin embargo, para asegurarte de **no romper nada** (por ejemplo, evitar que cierre un archivo sin guardar o un proceso crítico del sistema), es fundamental formular la pregunta con el contexto y las instrucciones adecuadas.

### 🎯 Estructura de un buen prompt:

```text
"Noto el ordenador caliente y no se apaga bien.
¿Puedes comprobar qué procesos están consumiendo más CPU/RAM?
No mates procesos del sistema ni cierres mi editor de código.
Si encuentras procesos de bases de datos o navegadores en segundo plano,
dime cuáles son y ciérralos de forma segura (graceful exit)."
```

### 💡 Ejemplos prácticos de preguntas que puedes hacerle:

#### 1. Para diagnosticar sin tocar nada (Modo seguro de solo lectura):
> *"Antigravity, revisa los procesos que más CPU están consumiendo en mi máquina ahora mismo y comprueba si hay servicios de bases de datos (MySQL, Postgres, Docker) activos de fondo. Solo quiero ver el diagnóstico."*

#### 2. Para limpiar de forma controlada:
> *"Veo que hay procesos huérfanos de Chrome/navegadores y servicios de base de datos consumiendo recursos. ¿Puedes cerrar todo lo que no sea indispensable excepto Antigravity, intentando un cierre limpio (SIGTERM / graceful quit) primero?"*

#### 3. Para evitar que vuelvan a encenderse solos:
> *"No quiero que MySQL y Postgres arranquen automáticamente cada vez que inicio el ordenador porque consumen mucha batería. ¿Cómo puedo deshabilitar su arranque automático en mi sistema?"*

## 7. La solución moderna: Por qué usamos Docker

Todo este dolor de cabeza de servicios que se quedan encendidos 24/7 en tu sistema operativo es exactamente **la razón por la que en la industria se utiliza Docker**.

* **Instalación tradicional:** Modifica tu sistema operativo, crea usuarios ocultos (`_mysql`, `postgres`), instala daemons que arrancan solos y consumen RAM continuamente.
* **Con Docker:** La base de datos es una caja aislada. Cuando terminas tu práctica, ejecutas:

```bash
docker stop nombre_del_contenedor
```

Y en ese mismo segundo, **el consumo de CPU y RAM vuelve a cero absoluto**, tu máquina se mantiene fría y el sistema operativo se apaga al instante sin ningún proceso fantasma reteniéndolo.
